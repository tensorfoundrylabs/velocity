# v2.0.1 - Component-aware pretty rendering

Build plan for inline field indicators in pretty/console mode. Opt-in, additive,
default-off, so JSON and existing console output are unchanged. Ships as **v2.0.1**.

## Motivation

Velocity is now multiplexing several services (Fleet, Scout, Relay) into one
console stream. Every line carries a `component` field as the first tree child,
plus recurring `count`, timing (`startup_ms`, `startup_time`, `stop_ms`, ...) and
state-transition (`old_state`/`new_state`, `prev_state`/`next_state`) fields.
Operators cannot scan it. We promote a small set of well-known fields to compact,
styled indicators on the header line. Pretty mode only. JSON and other structured
writers keep every field fully expanded.

Target look (full timestamp retained, exactly as today):

```
2026-05-30 14:52:33 [INFO] Scout   │ service started  discovery  [⏱ 2.0s · phase 0]
2026-05-30 14:52:56 [WARN] Scout   │ circuit breaker opened  192.168.0.181: closed → open
2026-05-30 14:53:04 [INFO] Relay   │ stopping services (4)
2026-05-30 14:53:04 [INFO] Fleet   │ Source state transition  relay-CODY-RYZEN: connected → stale
2026-05-30 14:53:04 [INFO] Fleet   │ Fleet has shutdown
```

Reading order: when (timestamp) - how bad (level) - who (component) - what (message).

## Design decisions (locked)

1. **Opt-in, default-off.** No behaviour change unless the user enables it. This is
   what keeps it a patch release. If at review we decide any preset
   (`WithDevelopment` etc.) should turn it on by default, that flips the release to
   **v2.1.0**. Default presets stay untouched in this plan.
2. **Component prefix:** `<name> │ ` placed after the level badge, before the
   message. Name left-padded to a fixed column width so the bars form a continuous
   vertical rule. Name carries an auto-generated colour; bar is muted-grey (the
   timestamp/`SlotMuted` colour) so it recedes as chrome. Thin `│` (U+2502), in the
   same box-drawing family as the field tree.
3. **Auto component colour:** deterministic hash (FNV-1a) of the component name into
   a curated per-theme palette. Same name maps to the same colour across processes,
   machines and restarts (FoundryOS runs these as separate processes in distributed
   mode, so first-seen assignment would diverge - a hash will not). Hash into a
   curated, contrast-checked palette, never raw RGB.
4. **Count:** ` (N)` appended after the message, reusing the existing `SlotCount`
   slot (purple in NightOwl). No new colour.
5. **Timing:** ` [⏱ Xms]` suffix. Glyph degrades to `[Xms]` when glyphs are off
   (env `VELOCITY_GLYPHS=0` or option), mirroring `hyperlink.go`. Timing field names
   are application-specific so there is no default set; the caller supplies them.
   Smart duration formatting (`2.7792897s` -> `2.78s`) applies only to the promoted
   token, not to tree values, so existing tree output is unchanged.
6. **State transitions:** when both keys of a configured pair are present, collapse
   to ` from → to` (arrow degrades to `->` when glyphs off). Pairs are configurable
   (default `old_state`/`new_state` and `prev_state`/`next_state`).
7. **Tree skip:** promoted fields are removed from the tree by default
   (`RemoveFromTree`, default true) so they are not shown twice.
8. **Reuse over new slots:** component-name colour comes from the palette, bar +
   timing reuse `SlotMuted`, count reuses `SlotCount`. No new `StyleSlot` values are
   strictly required (keeps the enum and every theme stable). A component palette
   array is added to the theme instead.
9. **Secure fields:** a promoted field that is `FieldTypeSecure`/`Redacted` on an
   untrusted writer is left in the tree (do not promote `[REDACTED]` to a prefix).
10. **Out of scope for this release:** `Logger.Status`/`Group`/`Continue` rich
    renderables (separate code paths, untouched); repeated-line dedup; relative
    timestamp eliding. Capture these as v2.1 follow-ups.

  Insert component prefix between `writeLevel` (112) and message (116); append count

## Public API additions (all opt-in)

`options.go`:

```go
WithComponentStyling()                    // convenience: component="component",
                                          // count={"count"}, state pairs old/new +
                                          // prev/next, glyphs auto. Timing stays
                                          // opt-in (names are app-specific).
WithComponentField(name string)           // enable component prefix, set field name
WithComponentColumnWidth(n int)           // pad width for the name column (default 8)
WithCountFields(names ...string)          // enable count promotion
WithTimingFields(names ...string)         // enable timing promotion
WithStateTransitionPairs(pairs ...[2]string) // enable arrow collapse
WithInlineGlyphs(enabled bool)            // override glyph auto-detection
```

`theme.go`:

```go
WithComponentPalette(colours ...Colour)   // ThemeOption: set the hash palette
WithComponentColour(name string, c Colour) // ThemeOption: pin one component (phase 1+)
```

Internal config struct on `config` (and copied onto `Template`):

```go
type inlineIndicators struct {
    component       bool
    componentField  string
    componentWidth  int
    countFields     []string   // small N, linear scan
    timingFields    []string
    statePairs      [][2]string
    showGlyphs      bool
    removeFromTree  bool        // default true
}
```

## Acceptance criteria

- Feature fully off by default; existing console + JSON output byte-identical (golden).
- With options on: component bar (hashed colour, aligned), `(N)` count, `[⏱ ...]`
  timing, `from → to` arrows render; promoted fields leave the tree; JSON still
  carries every field.
- Glyphs and colour degrade cleanly (`VELOCITY_GLYPHS=0`, `NO_COLOR`).
- No allocation regression for entries that match no promoted keys (perf-gate).
- New example builds and runs; `make ready` green.
